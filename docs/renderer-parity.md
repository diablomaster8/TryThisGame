# Renderer parity checklist (TECH-13)

Two renderers must show the same game: Pixel 2.5D (`src/render/`) and Full 3D
(`src/render3d/`). This is the single list of what has to match. A row is **checked** when a
test asks both renderers the same question; **open** rows name what is missing.

The shared vocabulary is `src/render-common/visual-state.ts` (`VisualState`). Full 3D's
`poseFor` is routed through it: `visualStateFor` names the state and `poseOfState` picks the
rig pose. Pixel's `clipFor` names a clip that maps into it, and `tests/render/parity.test.ts`
compares the two on 200 seeded Nubbin states. Known disagreements are listed in that test
(`KNOWN_GAPS`, shrink only; empty since 2026-11-04) and in the table below.

Petted: both name `petted`; 3D leans in (`pet`), Pixel draws its happy frames (no lean-in clip yet) |

need their own scenes there.
