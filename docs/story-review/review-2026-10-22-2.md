### Options

1. **One single file (Maor's literal idea).** 254k lines / 15 MB. Unreviewable in 400-line chunks, every diff lands in one file, slow on a phone, and an AI session cannot hold or grep it usefully. Works only for a *read-through* copy of one line, e.g. Hazel's Grove core (12k lines, under 1 MB).
2. **One book per line, chapters per quest, variants inline.** Better, but the edu books are still 70–90k lines and keep needing hand splits.
3. **One screenplay per storyline, folders by line, band versions as siblings, generated index.** Every file ≤ ~3,500 lines, one review unit each, diffs local, phone-sized. Cost: generator rewrite (~300 lines); LOG unit list remapped.
4. **Change the source of truth (YAML/Fountain compiled to TS).** Edu files are code (builders, line splitting, lesson indices); SWAPS and `childLines` depend on line positions; Atlas relies on filename globs; 22 tests import content. High risk, weeks of tooling, no gain the book cannot give. Reject.
5. **Book out of git.** Loses readable text diffs and the stable targets reviews cite. Keep it in git, add a sync check.

### Recommendation

Keep the TypeScript source exactly as it is. Restructure only the generated book (option 3), and add a generated, uncommitted single-file read-through per line to answer Maor's "one file with chapters" for reading straight through.

```
script-book/
  README.md            play-order index: every storyline, its files, line counts, review unit
  ids.tsv              scene id → book file:line → src file:line (for citing and grepping)
  campaign/
    book-1.md book-2.md book-3.md     chapters as ##, scenes in play order, notes inline
    endings.md triggered.md
  side/   S01.md … S31.md             variants under their parent scene
  fun/    python.md bean.md sunny.md avatar.md alice.md holmes.md hodja.md
  neopia/ line.md quests.md
  multiverse/ ironman.md … endgames.md
  expansions/ E1.md E2.md E3.md
  storylines/ beetle.md dawndusk.md hundred.md logged.md
  atlas/  A01/main.md A01/sprout.md A01/reader.md … A31/
  arcade/ PA1/main.md PA1/sprout.md PA1/reader.md …
  lines/  LB/ LK/ lang-hebrew/ lang-japanese/ (+ word lists)
  learning/campaign/ sprout.md reader.md   (split by book if > 3,500 lines)
  learning/side/ S01/sprout.md S01/reader.md …   learning/fun/ python/ bean/ avatar/
  extras/ readers.md results.md
```

Rules for the generator:
- One storyline per file, scenes in play order (by quest code, then step).
- Variants go directly under their parent scene. The parent comes from a small override map in `script-book.ts` (seeded by id prefix, e.g. `a14-16-sit-corvin` → `a14-16`). Anything unresolved goes in a "Variants" section at the end of *that storyline's* file, not the whole book.
- Each edu scene heading links to the main scene (`../main.md#a14-03-pylos`). Band versions stay in sibling files rather than side by side, which doesn't work at phone width.
- Hard cap: a file over 3,500 lines splits at quest headings into `-1`, `-2` (none expected today).
- `--whole <dir>`: writes one HTML (or Markdown) per line, with a table of contents: "Hazel's Grove" (campaign + side stories in play order), "Atlas", "Multiverse", "Learning Grove (sprout)", and so on. It is gitignored and published as a private Artifact when Maor wants to read straight through.

### Migration (small, safe steps; no game code touched)

1. **Sync check.** Add `--check` to `script-book.ts`: regenerate to a temp dir and diff, exit 1 on drift. Add it to CLAUDE.md's content validation list and the end-of-session checklist. Optionally add a Vitest wrapper so `npm test` catches drift.
2. **Coverage.** Add Alice, Holmes, Hodja, E1–E3 and the four storylines to the current layout, and regenerate. Mark them "never" in LOG.md.
3. **New layout.** Rewrite the output half of `script-book.ts` and emit `ids.tsv` and the new README. Delete the old 68 files in the same commit. Sort edu output by code. Do not touch `content-check.ts`: it reads `src/content/index`, which doesn't change.
4. **LOG.md remap.** Units become one storyline folder for the main game (`side/S09.md`, `atlas/A14/main.md`) and one file per band for edu. Carry "last reviewed" across by mapping (00 → campaign/*, 01/01b/01c → side/*, 20a/21a → learning/campaign/*). The ~3,200-line part rule is dropped. Open recs keep their scene ids, so only the unit column changes. Reviews cite `ids.tsv` lines instead of searching by hand.
5. **Read-through.** Add `--whole` and publish "Hazel's Grove" first (~12k lines).
6. **Optional, later:** add `src/content/` and `script-book/` to `.prettierignore`. Running `npm run format` today would rewrap 103 files and bury real text changes in diffs, and one dialogue line per source line is the better format for grep and review. Also record in CLAUDE.md that the ~800-line split rule doesn't apply to `src/content` data files: read them by grep range.

### Leave alone

- The TS source layout, file names (the Atlas glob parses `atlas-aNN.ts`), the aggregators and lazy chunks, the edu builder code, ids and the `reader:`/`sprout:` prefixes.
- SWAPS and `childLines` anchors. They are fragile because they depend on line positions, but restructuring the book doesn't change that. If they are hardened later, do it as separate work (for example, a check that every anchor resolves).
- `voiceover/` (a hand-made sample).
- Keeping the book in git. Its diffs are the readable changelog of the story.
